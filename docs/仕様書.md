# 資格学習ウェブアプリ 仕様書(ドラフト v0.2)

作成日: 2026-08-07(v0.2 同日改訂)
最初の対象試験: AWS Certified Generative AI Developer - Professional (AIP-C01)
ステータス: 機能の枠組みを決める段階。「未決事項」の節に決めるべきことをまとめている。

---

## 1. 目的・背景

- 手元の問題バンク(95問+今後作成するオリジナル問題)をブラウザで解けるようにする
- 正答率・習得状況を記録し、間違えた問題を復習できるようにする(現在チャットで行っている学習フローのウェブ版)
- 読み上げ音声(MP3)をウェブ上で聴けるようにする
- 自分以外の人にもURL共有で使ってもらう
- 学習データ(正答率など)はサーバーに持たず、**利用者それぞれのブラウザ内(ローカル)に保存**する
- **AWS AI資格に限定しない汎用の資格学習アプリとして設計する**。今後、他のAWS資格やAWS以外の資格も「試験」として追加していく(§3.0)
- 試験範囲や問題の改訂に追従できるよう、問題データの更新パイプライン(Claudeスキル)を整備する(§11)

## 2. 全体アーキテクチャ

**サーバーレスの静的サイト(SPA)+ ブラウザローカル保存** を基本とする。

- バックエンド(データベース・API サーバー)は持たない。ホスティングは静的ファイル配信のみ
- 進捗データは IndexedDB(容量が大きく構造化データ向き。localStorage より推奨)に保存
- AI連携(後述)は利用者自身の API キーでブラウザから直接 AI API を呼ぶ(キーも進捗もサーバーに送らない)
- PWA(Service Worker)対応により、2回目以降はオフラインでも問題演習・音声再生ができる

この構成の利点: ホスティング費用がほぼゼロ/個人情報を預からないので運営責任が軽い/利用者ごとのアカウント管理が不要。
欠点: 端末を変えると進捗が引き継がれない → 進捗のエクスポート/インポート機能で補う(§3.7)。

## 3. 機能仕様

### 3.0 複数試験(マルチ試験)対応 ★v0.2追加

- アプリの最上位に「試験」の概念を置く。例: 「AWS AIP-C01」「AWS SAA-C03」「基本情報技術者」…
- ホーム画面は試験の選択から始まり、進捗・統計・音声・用語集はすべて**試験ごとに分離**して管理する
- 試験は `exams.json`(試験一覧)+ 試験ごとのフォルダ(問題・音声・用語集・図)という構成で、**フォルダを追加するだけで新しい試験が増やせる**データ駆動設計にする

```
data/
  exams.json                  // [{id, name, description, domains:[...]}]
  aip-c01/
    questions.json            // 同梱セット(オリジナル問題)
    glossary.json
    audio/ *.mp3 + chapters.json
    figures/ *.svg
  saa-c03/
    ...
```

- 用語辞書は「共通辞書(AWS全般・IT一般)+試験別辞書」の2階層にし、試験をまたいで再利用できるようにする
- 進捗データも試験IDをキーに分離。エクスポート/インポートは試験単位と全体一括の両方に対応

### 3.1 問題演習(クイズ)モード

- 1問ずつ出題 → 回答 → 正誤判定+全選択肢の解説表示、の繰り返し(現在のチャット学習と同じ流れ)
- 対応形式: 複数選択(1つ/2つ/3つ選択)、並び替え(ドラッグ&ドロップ)、マッチング(プルダウンまたはドラッグ)
- 出題順モード:
  - **おまかせ(推奨・デフォルト)**: 要復習(直近不正解)> 未出題 > 再確認待ち(正解1回のみ)の優先度。同一問題は最低3問間隔を空ける ※現行 quiz.py と同じアルゴリズム
  - 順番どおり / ランダム / 要復習のみ / 未出題のみ / ブックマークのみ
- 習得判定: 2回連続正解で「習得済み」。不正解でリセット(まぐれ対策)
- 選択肢の並びをランダム化するオプション(記号の丸暗記防止)
- 各問題にブックマークとメモ(自由記入)を付けられる
- 模擬試験モード: n問をランダム抽出、制限時間タイマー付き、途中は正解を見せず最後にまとめて採点・レビュー

### 3.2 統計ダッシュボード

- 全体正答率、延べ回答数、習得済み/再確認待ち/要復習/未出題の内訳(ドーナツ/積み上げバー)
- 正答率の推移グラフ(日別)
- 出題元(問題集1/問題集2/オリジナル)別・試験ドメイン別の正答率
- 学習カレンダー(GitHub風ヒートマップ)と連続学習日数(ストリーク)
- 「苦手トップ10」(不正解回数順)から直接復習開始できる

### 3.3 音声ページ

- 既存のMP3(4ファイル)をそのまま配信し、ブラウザの audio プレイヤーで再生
- **連続再生(必須)**: ファイル末尾で次ファイルへ自動継続。プレイリスト全体のループ再生も可
- **再生速度変更(必須)**: 0.75〜2倍(音声自体が1.5倍速で作られているため、実効 約1.1〜3倍)
- 問題ごとのチャプターリスト(タップで頭出し)。※各問題の開始秒数はビルド時に生成してJSONで持つ
- 再生位置の記憶(次回続きから)
- PWA キャッシュによるオフライン再生(音声は容量が大きいので「オフライン用にダウンロード」を明示的なボタンにする)
- スマホのロック画面操作対応(Media Session API)

### 3.4 用語集(単語タップ解説)

- 問題文・選択肢・解説内の登録済み用語を自動でリンク化し、タップするとポップアップで用語解説を表示
- 用語辞書は**事前生成した glossary.json** を同梱(AWSサービス名、ML/GenAI用語 200〜300語を想定。Claude が一括生成する)
- ポップアップには「かんたん解説(2〜3文)」+「関連用語」+「この用語についてAIに聞く」ボタン(§3.6 連携)
- 全用語を事前に人手で書くのは非現実的なので、「事前辞書でカバー + 載っていない語はAI連携で補う」の二段構えとする

### 3.5 図解

- 問題ごとに構成図・概念図(SVG)を用意し、解説画面に表示
- 全問題に図を作るのはコストが高いため、段階的に整備する:
  1. まず「図があると理解が段違いに変わる問題」(アーキテクチャ系・フロー系、全体の3〜4割目安)から作成
  2. 図は Claude が Mermaid/SVG で下書き → 人がレビュー、のフローで量産
- 図のない問題は非表示(「図なし」表記はしない)

### 3.6 AI連携(オプション機能)

- 設定画面で利用者が自分の API キーを登録(Anthropic / OpenAI の両対応)。キーは IndexedDB にのみ保存し、外部送信はAI APIへの直接リクエストのみであることをUIに明記
- できること:
  - 問題・解説画面から「この問題についてAIに質問」(問題文+選択肢+解説をコンテキストとして自動添付したチャット)
  - 用語ポップアップの「AIに聞く」(用語+出現文脈を添付)
  - 「もっと簡単に説明して」「例え話で説明して」などのワンタッププリセット
- **予算管理(必須要件)**:
  - 月次予算上限(円 or ドル)を設定可能。デフォルトは低め(例: $2/月)
  - リクエストごとにトークン数から概算コストを計算・積算し、設定画面と各画面の隅に当月使用額を表示
  - 上限到達で AI機能を自動停止(手動で解除可能)
  - モデル選択可(安価モデルをデフォルトに)
- APIキー未設定でもアプリの他機能はすべて使える(AI連携はあくまで追加機能)
- 注意: ブラウザから AI API を直接呼ぶ構成のため、CORS の制約確認が必要(Anthropic は `anthropic-dangerous-direct-browser-access` ヘッダーで可)。キーの扱いは自己責任である旨を設定画面に明記

### 3.7 データ管理

- 進捗・設定・メモ・APIキー・使用額はすべてブラウザローカル(IndexedDB)
- **エクスポート/インポート**: 進捗一式をJSONファイルとしてダウンロード/読み込み(機種変更・ブラウザ変更対策。APIキーはエクスポート対象外)
- リセット(全消去)ボタン(誤操作防止の確認ダイアログ付き)
- 起動時にストレージ永続化(navigator.storage.persist)を要求し、ブラウザによる自動削除を防ぐ

### 3.8 問題データの二層構成(著作権対応)

- 問題データは「同梱セット」と「ローカル読み込みセット」の二層にする:
  - **同梱セット**: オリジナル問題(新規作成分)。サイトに含めて配信してよいもの
  - **ローカル読み込みセット**: AWS公式問題(現在の問題バンク95問)。サイトには含めず、利用者が手元の `問題バンク.json` をファイル選択で読み込むと使える。読み込んだデータもブラウザローカルにのみ保存
- こうしておくと、後で「全部公開はやめてオリジナルのみ」と方針変更しても作り直しが発生しない
- 音声ファイルはAWS公式問題を読み上げたものなので、同梱可否は公開方針の決定に従う(非公開・限定共有なら同梱可の判断もあり得る)

### 3.9 AI取り込み — キャプチャ/テキスト → 問題JSON変換 ★v0.2追加

- 問題データの追加は「所定スキーマのJSONを読み込む」が基本だが、APIキー設定済みの利用者向けに**AI変換ウィザード**を提供する
- 入力として受け付けるもの:
  1. **スクリーンショット画像**(問題画面のキャプチャ。複数枚まとめて可)→ Vision対応モデルで読み取り
  2. **テキスト貼り付け**(コピペした問題文・Skill Builderエクスポートの断片など)
- 処理フロー: 入力 → AIが問題スキーマ(§5.1)のJSONに構造化 → **プレビュー画面で人が確認・修正**(正解・解説の誤読み取り対策で必須ステップ) → ローカルセットに保存
- 複数問題の一括変換に対応。変換結果はエクスポートして他の人に配布することも可能
- 変換コストも §3.6 の予算管理に合算する
- 注意書き: 他者の著作物を取り込んで配布する場合の権利は利用者の責任である旨をUIに明記

## 5. データモデル

### 5.1 問題データ(既存形式を踏襲・拡張)

```json
{
  "id": "Q2-059",
  "source": "Q2",            // Q1 / Q2 / ORIG(オリジナル)
  "type": "choice",          // choice / ordering / matching
  "domain": "モデル評価",     // 統計用の分類タグ(要整備)
  "question": "...",
  "n_correct": 1,
  "options": [{"letter": "A", "text": "...", "correct": false, "explanation": "..."}],
  "order_answer": ["A","B"],  // ordering のみ
  "statements": [...],        // matching のみ
  "figure": "figures/Q2-059.svg",  // 任意
  "audio": {"file": 4, "start": 1234.5}  // 音声チャプター位置
}
```

### 5.2 進捗データ(IndexedDB)

```json
{
  "questions": {"Q2-059": {"attempts": [{"date": "...", "chosen": ["C"], "correct": false}],
                            "streak": 0, "bookmarked": false, "note": ""}},
  "history": [{"id": "Q2-059", "date": "...", "correct": false}],
  "settings": {...},
  "aiUsage": {"2026-08": {"usd": 0.42}}
}
```

### 5.3 用語辞書

```json
{"term": "SageMaker Clarify", "aliases": ["Clarify"], "short": "モデルのバイアス検出と説明可能性を提供するSageMakerの機能。", "related": ["バイアス", "説明可能性"]}
```

## 6. 技術スタック(提案)

- **フレームワーク**: Vite + React + TypeScript(実績・情報量重視)。※シンプルさ最優先なら Svelte でも可

## 7. ホスティング比較(未決)

| 案 | 費用 | アクセス制限 | 備考 |
|---|---|---|---|
| GitHub Pages | 無料 | ❌(URL秘匿のみ) | リポジトリと一体で最も手軽 |
| Netlify / Vercel | 無料枠(帯域100GB/月) | ❌ 無料では不可 | デプロイ最速。規模的に無料枠で十分 |
| AWS S3 + CloudFront | ほぼ0円(CFは1TB/月まで無料枠) | ⭕ CloudFront Functions で Basic認証 | AWS知識を活かせる。IaC化も可 |
| Cloudflare Pages + Access | 無料(Accessは50人まで) | ⭕ メール認証でアクセス制限 | 制限をきちんとかけたい場合の対抗馬 |

推奨: 「URLを知っている人だけ」の緩い運用なら GitHub Pages / Netlify。認証を付けたいなら S3+CloudFront か Cloudflare Pages+Access。

## 8. 追加アイデア(取捨選択してください)

1. **間隔反復(SRS)**: 習得済み問題も1日→3日→7日…と間隔を空けて自動再出題(忘却曲線対応)。現行の「2連続正解で習得」の自然な拡張
2. **キーボード操作**: PC利用時 A〜F キーで選択、Enter で回答、→ で次へ
3. **音声と演習の連動**: 演習画面に「この問題の音声を聴く」ボタン(チャプター頭出し再生)
4. **成績シェア画像**: 「正答率85%・習得60問」のようなカードを画像生成してSNS/友人に共有
5. **複数問題セットの切替**: 公式/オリジナル/将来の追加セットをタブで切替。セットごとに進捗を分離
6. **間違い理由のセルフタグ**: 不正解時に「知識不足/読み違い/ケアレスミス」を1タップ記録 → 統計で内訳表示
7. **オリジナル問題の一括投入フォーマット**: JSONを所定形式で置くだけで問題追加できるようにし、今後Claudeで問題を量産→即反映のパイプラインにする
8. **学習リマインダー**: PWA通知(任意許可)で「今日の10問」を通知

## 10. コンテンツ更新パイプライン(Claudeスキル) ★v0.2追加

試験範囲の改訂・問題の追加・新試験の立ち上げを、毎回ゼロから頼まなくても再現できるよう、
手順を **Claude スキル(quiz-content-update)** として整備する。スキルがカバーする作業:

1. **取り込み**: Skill Builder等のエクスポート(txt/HTML)や手書きメモから問題を抽出し、§5.1スキーマのJSONに変換
2. **検証**: 選択肢数と正解数の整合、解説と正解フラグの矛盾チェック、既存問題との重複検出
3. **統合**: 既存 questions.json へのマージ(IDの採番規則、試験フォルダへの配置)
4. **派生物の再生成**: 読み上げ音声(カタカナ辞書によるTTS変換)、チャプターJSON、用語辞書の差分追加
5. **オリジナル問題の作成**: 試験ガイドのドメイン配分に沿った新規問題の生成ルール

スキル本体は `SKILL.md`(+補助スクリプト)としてリポジトリに同梱し、Claudeのアカウントスキルにも登録しておく。
これにより「新しいエクスポートファイルを置いて『問題集を更新して』と言えば終わる」状態を目指す。

## 13. 問題の品質基準(2026-08-27 追加)

**この節が本アプリの中核。** 利用者の目的は合格であり、本番より易しい問題は数を揃えても価値がない。

### 基準の作り方

公式模擬試験(1290問)を分析して基準を作る。**実例を見せるだけでは伝わらない**ため、
守るべき数値・誤答の材料・制約の書き方を資格ごとにまとめる。

```
python tools/make_exam_guide.py        → 資料/作問ガイド/{EXAM}.md
```

問題を作る・直すときは必ずこのガイドを先に読む。

### チェックリスト

| ファイル | 内容 |
|---|---|
| `資料/生成/_review_criteria.md` | v1: 公式61問から導出した37項目 |
| `資料/生成/_review_criteria_v2.md` | **v2(確定版): 公式100問で検証した58項目**。各項目に機械判定の可否・重要度・公式の実例つき |

### 検証の手順

```
python tools/audit_all.py        全観点を一括実行(機械で測れない観点も「未検査」として表示)
python tools/audit_criteria.py   チェックリスト各項目の充足状況
```

**機械の検査が全部通っても品質は保証されない。** 58項目のうち機械で判定できるのは一部で、
残りはAIか人が読む必要がある。定期的に、公式問題と混ぜた出典を伏せた判定を行う。

### 実測されている品質差(2026-08-27 時点・要改善)

| 指標 | 公式 | 自作 |
|---|---|---|
| 正解と1点だけ違う誤答がある | 30.2% | **5.2%** |
| 2×2マトリクス構造 | 14.6% | **0.4%** |
| 「自前実装/手動」が正解になる | 11.8% | **0.8%** |
| 設定断片(JSON/ログ)を提示 | 5% | **0%** |

3つ目は特に重要で、自作では「手動と書いてあれば誤答」というメタ規則だけで解けてしまう。

作業の決まりは `CLAUDE.md`、現状と残作業は `HANDOFF.md` を参照。
